# UX 제안 (2026-07-05) — 근거 패널 · 탐색 엔트리포인트

> 사용자 피드백 2건에 대한 분석 + 기획 제안. 승인 시 각 항목을 태스크로 분할해 구현.
> 원칙은 기존 [`UX_SPEC.md`](./UX_SPEC.md) §1을 따른다(신뢰는 보이게 · 회색조 · 챗으로 되돌아감).

## 제안 A — 근거 패널 재설계 (EV-PANEL)

### 지금 무엇이 문제인가
현재 `ContextPanel`(Chat.tsx)은 **평면 수직 리스트**다:
```
근거 패널
─────────────
차트·표 N
답변에 사용된 출처 N      ← SourceCard 를 그냥 세로로 쌓음
  ▸ 참고한 모든 출처 (fold)
  ▸ 훑어본 도구 (fold)
```
문제:
1. **관계가 안 보인다.** 답변 본문의 `[n]`과 출처 카드가 서로 끊겨 있다 — 어떤 문장이 어떤 근거에 기대는지 눈으로 못 잇는다.
2. **한눈 요약이 없다.** "이 답이 공시 2건 + 매크로 1건 위에 서 있다"가 안 보이고, 카드를 하나씩 읽어야 안다.
3. **이미 만든 신호가 묻힌다.** QT-2 숫자 감사(checked/supported)와 검증 패스의 per-source confidence(high/med/low)가 이미 계산되는데 패널엔 노출이 약하다.
4. **출처 유형 구분이 없다.** 공시·뉴스·데이터/계산·매크로가 한 덩어리로 쌓인다.

### 제안: "신뢰 요약 → 근거 유형 그룹 → 양방향 연결"
```
┌ 근거 패널 ───────────────────────────────┐
│ ✓ 검증  숫자 8/8 자료 대조 · 출처 5 · 최신 🟢4 🟡1 │  ← ① 신뢰 요약 스트립
│ ────────────────────────────────────────  │
│ 📄 공시 2   📰 뉴스 1   📊 데이터·계산 2   🌐 매크로 1 │  ← ② 유형 칩(카운트) · 클릭=필터
│ ────────────────────────────────────────  │
│ 차트·표 (2)                                │
│  [artifact cards …]                        │
│ 답변 근거 (5)                              │
│  [1] 📄 AAPL 10-K · 위험요소   🟢 강함  ↗    │  ← ③ [n] 앵커가 카드에 박힘
│  [2] 📊 PER 계산근거            🟢 강함  ↗    │     본문 [n] hover ↔ 카드 하이라이트
│  …                                         │
│  ▸ 참고한 모든 출처 · 훑어본 도구           │
└────────────────────────────────────────────┘
```
- **① 신뢰 요약 스트립** (신규, 항상 상단): `msg.audit`(QT-2)에서 "숫자 N/N 대조", 출처 수, freshness 분포 도트. 감사 실패가 있으면 앰버로 "미확인 k건" — 신뢰 브랜드를 fine-print가 아니라 헤드라인으로.
- **② 근거 유형 칩**: `citation.kind`(filing/news/metric·data/macro)로 그룹핑 + 카운트. 칩 클릭 = 그 유형만 필터(로컬). "무엇 위에 서 있는지" 한 글자로.
- **③ 본문 [n] ↔ 카드 양방향 하이라이트**: DerivationCard의 심볼-칩 패턴을 재사용. 답변 프로즈의 `[n]`에 hover하면 해당 SourceCard가 하이라이트되고, 카드에 hover하면 본문 `[n]`이 강조. 각 카드에 confidence 배지(강함/보통/약함)를 명시.
- 기존 fold(참고한 모든 출처·도구)는 유지 — 아무것도 사라지지 않는다.

### 구현 태스크(안)
- **EV-1 (S)**: 신뢰 요약 스트립 — `msg.audit` + freshness 집계 렌더. (web only)
- **EV-2 (S)**: 근거 유형 칩 + 로컬 필터. (web only, `citation.kind` 이미 존재)
- **EV-3 (M)**: 본문 `[n]` ↔ SourceCard 양방향 하이라이트 + confidence 배지 표면화. (web; 앵커 파싱은 이미 있음 `has_anchors`/`anchor_markers`)
- 수용: vitest — 스트립이 audit에서 카운트를 렌더, 칩 필터가 유형별로 카드를 거른다, [n] hover가 매칭 카드에 `hot` 클래스.

## 제안 B — 탐색 엔트리포인트 재설계 (ENTRY)

### 지금 무엇이 문제인가
빈 탐색 화면(Chat.tsx `messages.length === 0`)에:
```
무엇이든 물어보세요
보유 종목, 뉴스, 시황, 경제 …
[DeskHome — 데스크 피드 카드]           ← 관심그룹/데이터 있어야 채워짐
[PromptWaterfall — 무한 루프로 흐르는 프롬프트]  ← 모션 노이즈, 압도적
  (또는 static EXAMPLES 칩 4개)
```
문제 (사용자: "뭘 해야할지 잘 모르겠어"):
1. **경쟁하는 3개 블록** — 헤딩 + 데스크 카드 + 워터폴이 동시에 시선을 끈다.
2. **무한 워터폴**이 계속 흐른다 → 읽기 어렵고 "고르는" 느낌이 아니라 "흘려보내는" 느낌.
3. **의도(intent)로 안내하지 않는다.** 우리 차별점(히스토리 랩·팩트체크·밸류에이션·근거)이 첫 화면에서 안 드러난다.
4. **blank-page paralysis** — 종목/질문을 동시에 떠올려야 한다.

### 제안: "무엇을 할지" 레인 → "어느 종목" → 능력별 질문 칩
```
┌ 탐색 (빈 상태) ─────────────────────────────┐
│  오늘 무엇을 살펴볼까요?                       │
│                                              │
│  ┌ 🔍 종목 조사 ┐ ┌ 🕰 과거와 비교 ┐ ┌ ✓ 팩트체크 ┐ │  ← ① 의도 레인 (4~5개)
│  │ 실적·밸류·  │ │ 지금 낙폭이   │ │ 들은 얘기   │ │     _CAPABILITY_MENU 기반
│  │ 공시·리스크 │ │ 역사에선?     │ │ 사실인가?   │ │     각 레인=모드+예시
│  └────────────┘ └──────────────┘ └───────────┘ │
│  ┌ 📰 시황·뉴스 ┐ ┌ 📊 밸류에이션 ┐             │
│                                              │
│  ── 또는 종목부터 ─────────────────────────── │
│  [종목 검색 / @관심그룹]  → 고르면 그 종목의    │  ← ② 종목 먼저 → 능력별 질문 칩
│                             능력별 질문 칩이 뜸  │     (follow-up 엔진 재사용)
│                                              │
│  오늘의 데스크 (관심그룹 있을 때만, 접힘 가능)   │  ← ③ 데스크는 보조로 강등
└────────────────────────────────────────────┘
```
- **① 의도 레인 (신규 핵심)**: 4~5개 카드 — `종목 조사` / `과거와 비교(히스토리 랩)` / `팩트체크` / `시황·뉴스` / `밸류에이션`. 각 레인은 `_CAPABILITY_MENU`의 실제 능력에 매핑. 탭 → 그 모드에 맞는 2~3개 구체 예시 질문(회색조 칩)으로 펼침 → 클릭 시 컴포저 채움(자동 전송 아님). 팩트체크 레인은 FC-4 토글과 연결.
- **② "종목부터" 경로**: 검색/관심그룹으로 종목 선택 → 그 종목에 대한 **능력-aware 질문 칩**(이미 있는 follow-up/`_CAPABILITY_MENU` 로직 재사용). blank-page를 "종목 고르기 + 질문 고르기" 두 단계로 쪼갬.
- **③ 데스크 피드 강등**: 무한 워터폴 **제거**(모션 노이즈), 데스크 피드는 관심그룹 있을 때만 하단 보조 영역으로. static EXAMPLES는 레인 예시로 흡수.
- **자연스러운 첫 클릭**을 하나 만들어 주는 게 목표 — 지금은 첫 클릭 지점이 모호하다.

### 구현 태스크(안)
- **ENTRY-1 (M)**: 의도 레인 컴포넌트 — 5개 레인 × 각 2~3 예시. 데이터는 클라이언트 상수(능력 카탈로그와 정합). 탭→예시 펼침→컴포저 채움.
- **ENTRY-2 (M)**: "종목부터" — 종목 검색/관심그룹 → 선택 종목의 능력별 질문 칩(follow-up 엔진 또는 `/api`의 capability suggest 재사용).
- **ENTRY-3 (S)**: 워터폴 제거, 데스크 피드 접이식 보조 영역으로 재배치.
- 수용: vitest — 레인 탭이 예시를 펼치고 클릭이 `onPick`으로 컴포저를 채운다(자동 전송 아님); 종목 선택이 능력 칩을 렌더.

## 우선순위 제안
근거 패널(A)이 **이미 만든 신뢰 신호를 드러내는** 저위험·고효과라 먼저 — EV-1·EV-2(둘 다 S, web-only). 그 다음 엔트리(B)는 첫인상을 바꾸는 만큼 ENTRY-1부터. 승인/수정 의견 주시면 태스크로 분할해 진행.
