# ASK — "물어보기" 표면 개편 스펙 (v1, 2026-07-05)

> 6개 결정: 팩트체크 제거 · 근거 패널 정리(+노트북, 챗 전용) · 네비 통합("물어보기") ·
> 첫 화면 재기획(사전 생성 질문거리 + Hot Trend, 5분 파이프라인) · 온보딩 재기획(관심종목 필수).
> 로드맵 태스크: **ASK-1 ~ ASK-6** (docs/ROADMAP.md에서 링크).

## 0. 설계 원칙 — 왜 이렇게 묶이나

이 6건은 하나의 이야기다: **"접속하면 3초 안에 '오늘 물어볼 것'이 보이고, 답을 받으면
근거가 옆에 서고, 마음에 든 근거는 노트북에 쌓인다."**

- 유저의 여정은 `온보딩(관심종목) → 물어보기 첫 화면(질문거리) → 챗(근거 패널) → 노트북`
  하나의 루프다. 첫 화면의 질문거리가 관심종목에서 나오므로 **온보딩에서 관심종목 등록은
  필수**가 된다 — 등록을 건너뛰면 첫 화면이 텅 빈다(제품이 스스로를 설명 못 함).
- 접속 시점에 LLM을 돌리면 3초를 못 지킨다 → **모든 첫 화면 콘텐츠는 사전 생성**(5분 주기),
  접속은 DB 읽기 한 번.
- 팩트체크는 intake 분기·verdict 카드·eval 3종을 유지비로 갖는데, 사용 흐름에서 겉돌았다
  (질문거리→챗 루프 밖의 별동 기능). 제거하고 신뢰는 **수치 원장(TrustStrip+Ledger)** 하나로
  일원화한다.

## ASK-3 — 근거 패널은 챗에만

- `ContextPanel`은 **대화에 메시지가 있을 때만** 마운트: `view==="explore" && 현재 대화에
  assistant 메시지 ≥1`. 첫 화면(CockpitEntry/AskEntry)에서는 그리드 자체가 2컬럼
  (`210px minmax(0,1fr)`) — 빈 패널이 첫 화면 옆에 서 있지 않는다.
- 스트리밍 시작(첫 assistant 청크)과 함께 패널이 스르륵 등장 → "답이 오면 근거가 선다"는
  제품 문법이 시각적으로 강화된다.

## ASK-4 — 네비: "물어보기" 하나

## ASK-5 — 물어보기 첫 화면: "오늘 물어볼 것"이 즉시 보인다

> **⚠ ASK-7(2026-07-06)이 이 섹션의 상당 부분을 대체한다** — 아래 ①(pulse strip/티커
> 테이프)은 삭제, ②는 "탭한 종목만 온디맨드 생성"으로, ③ Hot Trend는 "지금 뉴스에서"
> (news_feed, 10분)로 바뀌었다. 문서 맨 아래 **ASK-7** 섹션이 현행 계약.

### 문제
현재 CockpitEntry는 4개 섹션(펄스 스트립·제안 3장·내 종목 스트립·데스크 폴드)이 병렬
나열 — 복잡하고, 접속 시 desk-feed를 온디맨드 생성해 느리며, 질문거리가 3장뿐이라 빈약.

### 새 구조 (위→아래)
```
① 시장 한 줄 (pulse strip — 유지, 축소: 지수 5개 한 줄)
② 내 종목 질문거리   ← 관심종목별 딥한 질문 카드 (사전 생성, 핵심 섹션)
③ Hot Trend          ← 거시/미시/금융 전반 "지금 얘기되는 것" (사전 생성, 전역)
```
데스크 폴드(옛 카드 그리드)는 삭제. 모든 카드는 탭 → 컴포저 프리필(자동 전송 없음, 유지).

### ② 내 종목 질문거리 — per-ticker 사전 생성 (유저별 아님!)
- **생성 단위는 티커**: 어떤 유저든 관심종목에 있는 티커의 질문 풀은 같다. 유저별 생성은
  비용 폭발(유저 × 5분), 티커별 생성은 공유 캐시(전 유저 합집합 티커 × 5분, tiny 유니버스
  기준 6~10개). 첫 화면은 내 관심종목 티커들의 풀에서 카드를 조립만 한다.
- 카드 내용: 최신 데이터에 **기반**한 딥한 질문 3~5개/티커. 예:
  - "NVDA 이번 10-Q에서 재고자산이 전분기 대비 어떻게 움직였나?" (hook: 최신 공시 접수일)
  - "삼성전자 최근 5년 낙폭 분포에서 지금 위치는?" (hook: 오늘 등락)
  - hook(한 줄 근거: 무슨 데이터가 새로 왔는지) + question(프리필 텍스트) + 출처.
- deskfeed.py의 QT-2 수치 감사·인용 없는 hook 드랍 규칙 그대로 상속.

### ③ Hot Trend — 전역 사전 생성
- 유저 무관 전역 1세트: 거시(금리·환율·CPI)/미시(실적·공시 클러스터)/금융시장(지수·변동성)
  묶음 4~6장. 각 장 = 제목 + 두 줄 요약 + 탭하면 물어볼 질문 + 출처·as_of.
- **전망 금지 그대로**: "지금 이런 데이터가 나왔다"까지만. 해석·방향 제시 없음.

### 파이프라인 (5분 주기, 접속 시 LLM 0회)
- **어디서**: studio-api의 기존 asyncio 스케줄러 패턴(scheduler.py, alerts)을 따라
  `feed_refresher` 루프 추가. worker(Procrastinate)는 datasets 소속이라 LLM 호출 부적합 —
  LLM은 agent-engine 라우터만(invariant #7), 워치리스트·유저 데이터는 studio-api 소유.
- **흐름**: 5분마다 studio-api가 ① 전 유저 관심종목 티커 합집합 수집 → ② agent-engine
  `POST /agent/ask-feed` (신규, desk-feed와 동일 계약: 게이트웨이 경유 데이터 수집 + Gemini
  합성 + QT-2 감사) 를 티커 배치·hot-trend 각 1회 호출 → ③ 결과를 `ask_feed_cache` 테이블
  (scope: `ticker:{mkt}:{tkr}` | `hot_trend`, payload jsonb, generated_at)에 upsert.
- **읽기**: `GET /ask-feed` (studio-api) = 내 관심종목 티커들의 캐시 + hot_trend 캐시 조립.
  캐시 미스(신규 티커) → 그 티커만 즉석 생성 큐잉, 화면엔 "준비 중" 스켈레톤(날조 금지).
- **비용 가드**: 데이터 서명(최신 공시 accession·마지막 뉴스 id·종가 날짜)이 그대로면 Gemini
  재합성 스킵 — 5분마다 도는 건 서명 체크, LLM은 데이터가 실제로 새로울 때만.
- env: `ASK_FEED_REFRESH_SECONDS=300`, `ASK_FEED_ENABLED=true`.

## ASK-6 — 온보딩: 서비스를 설명하고, 관심종목을 반드시 받는다

### 문제
현재: 시장 → 프리셋 그룹 → (알림) → 착륙. 서비스가 뭔지 설명이 없고, 관심종목을 건너뛸
수 있어 첫 화면이 빈다. 알림 스텝은 FLAG-1로 죽은 가지.

### 새 플로우 (3스텝, 알림 스텝 삭제)
1. **소개** — 한 화면, 세 문장의 제품 약속:
   - "**물어보면, 출처와 함께 답합니다**" (모든 숫자에 [n] 출처 — 수치 원장 미리보기 그림)
   - "**관심종목을 등록하면, 물어볼 거리를 먼저 준비해둡니다**" (첫 화면 미리보기 그림)
   - "**전망은 하지 않습니다** — 과거 기록·현재 데이터만" (신뢰 브랜드를 온보딩에서 선언)
2. **관심종목 등록 (필수, 최소 3종목)** — 건너뛰기 없음. "첫 화면이 이 종목들로 채워집니다"
   문구로 왜 필수인지 설명. 시장 토글(KR/US/둘 다) + 프리셋 그룹 원탭 + 티커 검색 추가.
   진행 버튼은 3종목 채우기 전 비활성(카운터 "2/3 선택됨").
3. **착륙** — 등록 종목 확인 + "물어보기로 가기". 착륙 즉시 ask-feed가 해당 티커 생성을
   큐잉(첫 카드가 수 분 내 등장; 그때까지 pulse+Hot Trend가 화면을 지킨다).

- 알림/대시보드 스텝·템플릿 생성 제거(FLAG-1 사망 가지 정리). `/api/onboarded` 계약 유지.

## ASK-7 (2026-07-06) — 근거 패널 v3 · 엔트리 v4 (현행 계약)

### A. 근거 패널 v3 — 스트리밍→완료가 "정리"로 읽힌다
문제: 수집 중 도착순으로 쌓이던 카드가 답변 완성 순간 전혀 다른 6개 섹션으로 재배열 —
과정이 안 읽히고, 어떤 출처가 실제 인용됐는지·[n]이 뭘 가리키는지 불명확.

- **수집 중**: `리서치 과정`(도구 타임라인, 마지막 스피너) → `차트·표` → `수집한 출처`
  (도착순 + "답변이 완성되면 **인용한 출처 [n]**과 **참고만 한 출처**로 정리돼요" 예고).
- **완료**: `판정(TrustStrip)` → `차트·표` → `인용한 출처 [n]`(번호순, 항상 펼침 — 본문
  [n]의 도착지) → `수치 원장` → `참고만 한 출처`(접힘·흐림) → `리서치 과정`(접힘 보존).
- 섹션마다 한 줄 설명(ctx-desc)이 "뭘 어떻게 봐야 하는지"를 직접 말한다. 카드 key는 출처
  identity(source|url)라 전환에도 같은 카드가 유지. [n] 배지는 filing/data/web 카드 공통.
- 근거/핀 액션 용어는 "노트북"으로 통일 (＋ 노트북 · 노트북에 담기). "대시보드"는
  피처플래그 꺼진 Board 표면에만 남는다.

### B. 엔트리 v4 — 종목은 탭할 때만, 뉴스는 백그라운드
- **티커 테이프 삭제** (pulse strip 미사용; `/market/pulse` 엔드포인트는 존치).
- **내 관심종목 파고들기**: 전 티커 사전 생성(전 유저 합집합 × 5분 스윕 — 느리고 비쌈)을
  버리고, **유저가 종목 칩을 탭한 순간** `GET /ask-feed/ticker?market&ticker&name`으로
  최신 기록 기반 카드 **3개**를 준비. studio-api가 scope `ticker:{MKT}:{TKR}` 캐시를
  `ASK_FEED_TICKER_TTL_SECONDS`(30분) 내 재사용, 서명 동일 시 LLM 스킵+TTL 갱신.
  실패/빈 결과 = 정직한 공백 + capability 칩("직접 물어보기") — 날조 금지.
- **지금 뉴스에서** (Hot Trend 대체): `news_feed` 스코프 — google_news US/KR 시장 전반
  헤드라인 + 지수 스냅샷을 10분 주기(`ASK_FEED_REFRESH_SECONDS=600`) 백그라운드 갱신,
  Gemini가 "중요한 뉴스"만 골라 궁금증을 자아내는 질문 카드로 합성(kind: macro|micro|market).
  백그라운드 리프레셔가 도는 스코프는 **news_feed 하나뿐**.
- `GET /ask-feed` 응답: `{groups, tickers[{market,ticker,name,groups}], news_feed[], news_generated_at}`
  (tickers에 cards 없음 — pending 개념 삭제).
