# 제안 1 — 근거 패널: “출처 목록”에서 “수치 원장(Figure Ledger)”으로

## 1.1 진단 — 무엇이 진짜 문제인가

현재 구조 (`Chat.tsx` ContextPanel):

```
근거 패널
  차트·표 N            ← ArtifactCard 세로 나열
  답변에 사용된 출처 N   ← SourceCard 세로 나열 (문서 단위)
  ▸ 참고한 모든 출처     ← fold
  ▸ 훑어본 도구         ← fold
```

표면 증상은 “linear한 출처 나열”이지만, 근본 문제는 **패널의 단위가 잘못되어 있다**는 것이다.
독자가 답변을 읽으며 갖는 질문은 4가지다:

| # | 독자의 질문 | 현재 패널의 답 |
|---|---|---|
| Q1 | “**이 숫자** 어디서 왔어?” | ✗ — 문장 속 [n]과 카드가 끊겨 있어 눈으로 못 잇는다 |
| Q2 | “이 답이 **무엇 위에** 서 있어?” | △ — 카드를 다 읽어야 구성이 보인다 |
| Q3 | “**믿을 만해?**” | ✗ — QT-2 숫자 감사·confidence·신선도가 계산되고도 묻혀 있다 |
| Q4 | “**원문** 보여줘” | ✓ — SourceViewer는 잘 작동한다 |

즉 패널은 Q4만 풀고 있다. 그런데 **금융에서 신뢰의 원자 단위는 문서가 아니라 숫자다.**
“매출 4,161억 달러”라는 주장 하나하나가 검증 대상이고, 우리는 이미 그걸 기계로 검증한다
(QT-2 감사: 모든 수치를 도구 반환값과 대조). 문제는 그 결과를 `✓ 8개 대조`라는 집계 한 줄로
버리고 있다는 것 — **원장(ledger)이 있는데 잔고만 보여주는 셈이다.**

## 1.2 콘셉트 — 3층 신뢰 구조: 판정 → 원장 → 원문

패널의 단위를 문서에서 **수치(주장)**로 뒤집는다. 모든 답변은 자동으로 다음 3층을 갖는다:

```
┌ 근거 패널 ────────────────────────────────────────────┐
│ ── ① 판정 (한 줄, 항상 상단) ────────────────────────  │
│  ✓ 검증 완료 — 수치 8/8 원자료 대조 · 출처 5 · 🟢4 🟡1   │
│                                                        │
│ ── ② 차트·표 (있으면) ───────────────────────────────  │
│  [artifact cards…]                                     │
│                                                        │
│ ── ③ 수치 원장 (패널의 새 심장) ──────────────────────  │
│  이 답변의 모든 숫자, 한 줄에 하나                        │
│  ┌──────────────────────────────────────────────────┐ │
│  │ 4,161.6억$   매출(FY2025)    [1] SEC 10-K   🟢 원문↗│ │
│  │ 63.6x        PER             [2] 계산 🧮    🟢  ↗  │ │  ← 파생값은 🧮 (클릭=Derivation Card)
│  │ −8.2%        현재 낙폭        [3] 히스토리    🟢  ↗  │ │
│  │ 15조원       (답변 표현)      ⚠ 미확인 — 원자료 불일치│ │  ← 감사 실패는 앰버로 정직하게
│  └──────────────────────────────────────────────────┘ │
│   행 hover ↔ 본문의 해당 숫자 하이라이트 (양방향)          │
│   행 클릭  → SourceViewer (파생값이면 도출 카드 본문)      │
│                                                        │
│ ▸ 문서 서랍 — 출처 문서 5 (기존 SourceCard, 접힘)         │
│ ▸ 과정 — 도구 실행 로그 (thinking 스트림 재구성, 접힘)     │
└────────────────────────────────────────────────────────┘
```

**층별 역할**
- **① 판정**: Q3의 답. QT-2 결과를 헤드라인으로 — 전부 대조되면 조용한 확인, 미확인이 있으면
  앰버 경고(개수+어느 수치인지 원장에서 표시). “신뢰가 브랜드”를 fine-print에서 헤드라인으로.
- **③ 수치 원장**: Q1·Q2의 답. **답변 프로즈에 등장한 모든 클레임 수치**가 행으로:
  `값(mono) · 의미 라벨 · 출처[n] · 신선도 · 원문↗`. 파생값(PER·DCF·낙폭)은 🧮 아이콘 —
  클릭 시 SourceViewer가 **Derivation Card를 본문으로** 연다(DRV-3, 이미 구축됨). 원장 행과
  본문 숫자는 양방향 hover 하이라이트로 물리적으로 이어진다.
- **문서 서랍**: Q4. 기존 SourceCard는 사라지지 않고 접힌 서랍으로 이동 — 문서 단위로 훑고
  싶을 때(공시 전체 읽기 등) 쓴다. “참고한 모든 출처”·“훑어본 도구”도 이 층에 흡수.

**왜 이게 맞는가**
1. 제품 불변식 #1(“출처 없는 숫자는 없다”)의 **UI 등가물**이다 — 규칙이 아니라 화면으로 보인다.
2. 경쟁 제품(Perplexity 등)은 문서 각주까지만 간다. **숫자 단위 원장 + 원문 셀 하이라이트 +
   파생값 도출 카드**의 3연타는 우리 데이터 플레인에서만 가능한 차별점이다.
3. 공유·팩트체크와 정합: verdict 카드의 findings, 공유 카드의 감사 게이트 모두 “수치 단위
   신뢰”를 전제한다 — 패널만 문서 단위로 남아 있던 것.

## 1.3 인터랙션 상세

| 상황 | 동작 |
|---|---|
| 스트리밍 중 | ①은 “수집 중” 스피너, 원장은 수치가 검증되는 대로 행이 자라남 (라이브 신뢰 형성 과정 자체가 쇼) |
| 원장 행 hover | 본문의 해당 숫자에 `mark` 하이라이트 + 스크롤 인디케이터; 반대로 본문 숫자 hover 시 행 하이라이트 |
| 원장 행 클릭 | SourceViewer 오픈 — 공시값이면 원문 셀 하이라이트, 파생값이면 Derivation Card 본문 |
| ⚠ 미확인 행 | 클릭 시 툴팁: “이 수치는 이번 턴 도구 반환값과 일치하지 않았습니다” + 해당 문장으로 스크롤. 공유는 이미 422로 막힘(기존 QT-2 게이트) — 이유가 이제 눈에 보인다 |
| 수치 0개 답변(개념 설명) | 원장 생략, ①은 “개념 설명 — 수치 없음”으로 강등. 패널이 억지로 채우지 않음 |
| 과거 답변 클릭 | 기존과 동일 — 그 턴의 원장으로 패널 재포커스 |

접근성: 행·본문 하이라이트는 색+밑줄 이중 부호화, 키보드 포커스로 hover 동작 동일 제공.

# 제안 2 — 탐색 엔트리: “메뉴”가 아니라 “관제탑 컴포저”

## 2.1 진단 — 왜 “뭘 해야 할지 모르겠”는가

현재 빈 탐색 화면:

```
무엇이든 물어보세요                ← 일반론 헤딩 (아무 정보 없음)
보유 종목, 뉴스, 시황, 경제 …
[오늘의 데스크 카드 그리드]         ← 관심그룹 있어야 채워짐; 없으면 넛지
[PromptWaterfall 무한 흐름]        ← 계속 움직여서 "읽는" 게 아니라 "흘려보냄"
(작은 컴포저는 화면 맨 아래)
```

문제의 구조:
1. **초점이 3개** — 헤딩·카드 그리드·움직이는 워터폴이 경쟁한다. 첫 클릭 지점이 없다.
2. **모션이 독해를 방해** — 무한 워터폴은 “고르기”가 아니라 “구경”을 유도한다.
3. **추상 → 추상** — “무엇이든 물어보세요”는 사용자가 이미 못 하는 일(질문 만들기)을 다시 요구한다.
4. **행동 불일치** — EXAMPLES 칩은 **즉시 전송**, 데스크 카드는 **컴포저 채움**. 같은 화면에서
   탭의 결과가 달라 신뢰 학습이 안 된다.
5. 정작 **컴포저(제품의 심장)는 화면 맨 아래 구석**에 있다.

핵심 통찰: 금융 사용자는 추상적 “의도”를 들고 오지 않는다. **(a) 머리에 있는 종목**이나
**(b) “오늘 뭐 있었지”**로 들어온다. 그리고 우리 제품의 첫 화면은 **검색엔진과 같은 문법**이어야
한다 — 리서치 데스크의 유일한 동사는 “묻는다”이므로, **입력창이 곧 엔트리포인트**여야 한다.
(v1의 “의도 레인” 5분류는 또 하나의 메뉴 분류학을 읽게 만드는 안이라 폐기.)

## 2.2 콘셉트 — Cockpit: 시장 한 줄 + 중앙 컴포저 + 타이핑이 곧 추천

```
┌ 탐색 (빈 상태) ──────────────────────────────────────────────┐
│  S&P 6,213 ▼0.4% · 코스피 3,120 ▲1.1% · 환율 1,368 · VIX 14.2  │ ← ① 시장 오프닝 스트립 (라이브·탭=질문)
│                                                              │
│            오늘의 시장, 무엇이 궁금하세요?                       │
│  ┌──────────────────────────────────────────────────────┐    │
│  │  삼성전자 실적이 어땠는지 물어보세요…            [✓팩트체크]│    │ ← ② 중앙 대형 컴포저
│  └──────────────────────────────────────────────────────┘    │    (플레이스홀더 = 오늘 기준 실제 질문 순환)
│   ↳ 포커스 시:                                                │
│   ┌ 오늘 물어볼 만한 것 ────────────────────────────┐          │
│   │ ▸ TSLA 실적 발표 D-2 — 컨센서스 확인해보기        │          │ ← ③ 제안은 딱 3개, 컴포저에 붙은
│   │ ▸ 코스피 +1.1% — 반도체가 끌었는지 보기           │          │    ghost 리스트 (데스크 피드 재사용)
│   │ ▸ 지금 S&P 낙폭, 과거 조정과 비교해보기           │          │    ↑↓+Enter로 선택 가능
│   └──────────────────────────────────────────────────┘        │
│                                                              │
│  내 종목   [🟦 삼성전자 ▲1.2%] [🍎 AAPL ▼0.8%] [⚡NVDA ▲2.1%]  │ ← ④ 워치리스트 티커 스트립
│   ↳ 티커 탭: ┌ 삼성전자에 대해 ─────────────────────┐          │    탭 → 그 종목 능력 칩 (전송 아님)
│              │ 실적 · 차트 · 공시 · 밸류에이션 · 뉴스  │          │
│              │ · 과거 낙폭 비교 · 수급(외인/기관)      │          │
│              └──────────────────────────────────────┘          │
│                                                              │
│  ▸ 오늘의 데스크 (접힘 — 브리핑 공유는 여기)                      │ ← ⑤ 데스크는 보조로 강등
└──────────────────────────────────────────────────────────────┘
```

**요소별 설계 근거**

**① 시장 오프닝 스트립** — “오늘 뭐 있었지”에 3초 안에 답하고, 각 항목이 **탭 가능한 질문**이다
(“코스피 ▲1.1%” 탭 → “오늘 코스피가 왜 올랐어?” 컴포저 채움). 데이터는 기존
`yahoo__asset_classes` 스냅샷 재사용 + 60초 캐시. 모든 숫자에 as_of 툴팁(신뢰 문법 유지).

**② 중앙 대형 컴포저** — 화면의 유일한 초점. 하단 고정 컴포저와 별개가 아니라 **같은 컴포저가
빈 상태에서만 중앙·확대 배치**(대화 시작 시 아래로 도킹 — Perplexity 패턴). 플레이스홀더는
정적 문구가 아니라 **오늘 기준 실제 질문이 4초 간격 순환**(데스크 피드의 question 필드 재사용;
피드가 없으면 능력 카탈로그의 정적 3종). 모션은 이 플레이스홀더 하나에만 허용 — 워터폴 제거.

**③ 포커스-제안 3개** — 입력창을 누르는 순간(의도가 “묻기”로 확정된 순간) 데스크 피드 상위
3개가 ghost 리스트로 붙는다. 카드 그리드가 아니라 **자동완성의 문법**(↑↓ + Enter)이라 배우지
않아도 안다. 각 항목은 `hook → question` 구조 그대로: 사실(출처 포함)이 왜 이 질문인지 설명한다.

**④ 티커 스트립 + 능력 칩** — “종목이 머리에 있는” 사용자의 경로. 관심그룹 티커가 등락과 함께
한 줄로(로고+등락 — 기존 terminal-UX 방향), 탭하면 그 종목의 **능력 칩 7개**(실적/차트/공시/
밸류/뉴스/과거 낙폭/수급 — KR이면 수급 포함, US면 13F로 치환). 칩 탭 = 완성된 질문을 컴포저에
채움. **blank-page를 “종목 고르기 → 질문 고르기” 2-스텝으로 분해**한다. 컴포저에 티커/종목명을
직접 타이핑해도 같은 칩이 인라인으로 뜬다(자동완성 결합 — ⌘K(UX-2)의 선행 구현이 됨).
관심그룹이 없으면 이 자리가 곧 넛지: 검색창 + “관심그룹으로 저장” — 기존 온보딩 프리셋 재사용.

**⑤ 데스크 접이** — 카드 그리드는 “▸ 오늘의 데스크”로 접힘(펼치면 기존 그대로 + 브리핑 공유
버튼 유지). 그리드는 훑기용이지 첫 행동 유도용이 아니었다는 진단의 귀결.

**전역 규칙** — 이 화면의 **모든 탭은 컴포저를 채운다. 절대 자동 전송하지 않는다**
(현 EXAMPLES의 auto-send 제거). 마지막 확정은 항상 사용자의 Enter — 통제감이 신뢰의 일부다.

## 2.6 대안 비교 (왜 이 안인가)

| 접근 | 장점 | 왜 탈락 |
|---|---|---|
| 의도 레인 메뉴 (v1) | 능력 노출 | 사용자가 분류학을 먼저 해석해야 함 — “뭘 해야 할지” 문제를 한 겹 위로 옮길 뿐 |

## 2.7 성공 지표
- **빈 화면 → 첫 질문 전송까지 시간** (핵심; 현 플로우 대비 단축)
- 제안/칩 경유 첫 질문 비율 vs 직접 타이핑 비율 (경유율이 높으면 추천이 작동)
- 첫 세션 2번째 질문 도달률 (엔트리가 좋으면 팔로업으로 이어짐)
- 관심그룹 생성 전환율 (④의 콜드 넛지 효과)

# 우선순위·일정 제안

두 제안은 파일 겹침이 없어 병행 가능. 추천 순서:
1. **LG-1→LG-3** (원장 코어) — 백엔드 1 + 프론트 2. 제품의 신뢰 서사를 완성하는 쪽이 먼저.
2. **ENT-1→ENT-5** — 첫인상 개편. ENT-2·5는 S라 사이에 끼워 넣기 좋음.
3. LG-4·5, ENT-3·4 마무리.

총 규모: M×5 + S×5 안팎. 모든 태스크는 기존 하네스(vitest·pytest·eval)로 수용 기준 검증.
